# NOCTILUCA — 次の便で

Sitesの認証・サーバー処理・D1で、一人ずつ異なる旅を保存する初版。
九つの惑星を巡る車窓と、序章・四章・終章を一本につなぐ。

## ロリポップデプロイなう版

現在版とは独立した公開版を用意しています。ロリポップには静的フロント、SupabaseにはAuth・Edge Function・PostgreSQLを配置します。セットアップとデプロイ手順は [`lolipop/README.md`](lolipop/README.md) を参照してください。

## 遊べる範囲

| 章 | 舞台 | 判断と、その後 |
| --- | --- | --- |
| 序章 | 九龍 | 静かな耳／夜更けのお茶／椅子の帰り便／雨の日の傘置き |
| 第一章・ひと箱の灯り | 九龍／スクラップ | メイかレンへ電源を販売。再訪して用途を知り、トレー／遮光フードの追加商売をするか見送る |
| 第二章・違う場所の使い方 | 蒼海／峡谷 | 小型・大型の密閉容器、または見送り。昇降機に載る品と麓で使う品の違いを知る |
| 第三章・渡したあとは | 翡翠／九龍 | 作業ラックの使い方を観察。理由を聞く・たずねない・商売を見送る。最初の取引先へ戻る |
| 第四章・返事のない仕事 | リレー／スクラップ | 保守端末への交換ブラシ納品、または見送り。整備機械の稼働を確認 |
| 終章・次の便で | 九龍の車窓 | 実際の判断を五ページの帳面で振り返り、次に使い手へ聞きたい一行を残す |

章は意味のある会話の完了や明示的な観察・判断で進む。「まだ考える」は保留、「今回は扱わない」は確定した判断。
最初の電源取引以降は、追加商売を見送っても終章へ進める。商売を始めず眺め続けることもできる。
終章後も列車は走り、会話・設備・帳面が残る。未消化の既存取引は可能。無制限の繰り返し商売、新惑星、数値好感度、自由歩行は初版に含めない。

設備は永続状態、台を出す便・ラックに載る物・雨は日常の表示。ログアウト中の時間で物語や設備は変化しない。
ホームのCanvas描画は、夜食台・表示盤・容器の置き場所・作業ラック・機械の交換ブラシを保存状態に合わせて表示する。

## 車窓の区画

9都市それぞれに4区画（駅前＋3区画）を用意。自動周遊とポモドーロでは、駅前から都市ごとの順序で外縁へ向かい、宇宙区間を経て次の街へ近づく。時間設定は各区画の滞在時間に反映し、同じ区画の短周期巡回や、速度変更による順序の巻き戻りは起こさない。切り替えは最大3秒、短い設定では短縮する。自動周遊をオフにした「この星を、ずっと」では、従来の約22秒ごとの巡回と再訪による順序の変化を残す。
停車時は駅前へ戻り、ホームの保存済み設備を表示する。区画は訪問数や物語の進行を増やさず、D1には保存しない。一時停止中は進めず、既存の動きの密度設定に従う。通常の車窓は非表示中も停止する。ポモドーロは既存の実時間タイマーに合わせ、戻った時点の残り時間から景色を復元する。到着前の景色は描画のみで、保存・訪問回数・ベルは既存の到着確定処理が担当する。
`src/client/scenery.js`が区画データ・走行中の切替・描画を担当し、描画済みレイヤーは切替に必要な2区画まで保持する。

| 深藍アビス | 気密ドーム街／珊瑚の居住塔／海溝の研究所／昆布の水耕畑 | クジラの影／クラゲの群れ／窓の修理／調査艇の帰還／昆布の収穫 |
| 紅蓮カルデラ | 溶岩運河の街／鋳造街／地熱発電の塔群／火口縁の湯の町 | 噴火の火柱／灰の掃除／大鋳込み／蒸気の噴出／天灯の打ち上げ |

空・4区画の建物・住人・手前の粒子(泡、火の粉、雲)は `src/client/frontier-scenes.js`、出来事は `src/client/frontier-moments.js` が担当する。出来事の抽選は他の星と同じ仕組みで、保存や進行には関わらない。行き先の検証はサーバーの `WORLDS` に3つを追加しただけで、旧セーブは訪問回数0として扱う。

## 九龍の小さな出来事

市場の常設店「猫灯 / NEKO AKARI」に、猫耳端末をつけた店員と猫型配膳機を配置。配膳時の譲り合い、窓拭き、看板修理、配達人の雨支度、屋台の店じまい、運河の舟の譲り合い、洗濯物の取り込み、メイの夜食台の椅子戻しの8種類を用意する。

`kowloon-moments.js` が便ごとの抽選・進行・描画を担当。通常便は0〜2件、長い滞在は4〜7件を上限として、見えている地区、雨の強さ、保存済みの夜食台と当日の営業状態で候補を絞る。上限まで必ず発生するわけではない。同時に1件、同じ便での再発なし、直前の便の出来事は抽選の重みを下げる。時間は表示中のアニメーション時間だけ進み、描画や縮小画像生成では抽選しない。

片付け結果はその便のメモリ内に残り、地区の往復では戻らない。再訪・ページ再読み込みでは新しく構成する。出来事自体をD1の発見フラグにせず、報酬・通知・進行条件を追加しない。既存の設備や物語の保存は従来どおり。

## 向かいの席の乗客

車窓の手前、向かいのロングシートに他の乗客が座る。駅に着くたび、無し・一人・二人組・三人組のいずれかが乗り込み、通路を歩いて空いた席に座る。乗っている乗客は数駅のうちに降りる。車内の猫と荷物、停車中の駅名パネルの裏は避けて座る。

一人の乗客は本を読む、端末を見る、うたた寝するなどして過ごすだけで、会話は生まれない。二人組（友人・恋人・同僚・きょうだい）は雑談や口げんか、三人組（友人・同僚・学生）は旅行の相談や冷やかし合いを、座席の上の吹き出しで交わす。話し手に顔を向け、口げんかでは腕を組んでそっぽを向く。

車窓右上のヘッドホンのボタンをオンにすると、乗客は会話を続けるが吹き出しは出なくなる(集中したいとき用)。オンの間はテンプレートの会話だけを使い、ロリポップ版の時事ネタの会話は消費しない。設定はこの端末のブラウザに保存する。

会話は話題テンプレートに駅名・次の行き先・食べ物・忘れ物などの語を組み合わせて毎回生成する。会話画面やホームの話し声が出ている間は進めず、一時停止中は止まる。乗客は表示のみで、保存・通知・進行条件には関係しない。`src/client/passengers.js`が生成・乗降・描画を担当する。

## 寄り道の依頼帳

「商売帳（所持金・荷物）」の隣の「寄り道の依頼帳」から開く。6駅に各4件、計24件。駅で下車し、条件を最後まで聞いてから引き受ける。仕入れ、探し物、預かり配送、情報収集が1件ずつあり、期限はない。情報収集は荷物棚を使わず、本編の荷物を運んでいる途中でも進められる。

| 駅 | 4件の依頼 |
| --- | --- |
| 九龍 | 静かな耳／夜の茶／椅子の返却／雨の日の傘置き |
| スクラップ・ベルト | 油のついた手でも／休憩室のまぶしい窓／温室へ返す道具／手袋の干し場所 |
| 蒼海ドック | 昼飯は、こっち／窓の向こうまで／棚に余ったカップ／潮待ちの腰掛け |
| 岩海峡谷 | 風にめくられない頁／長い袋の肩当て／鉢の下に、谷の石／猫は下りに乗らない |
| 翡翠ガーデン | 小さな葉に届く雨／結び直せる輪／交換会の敷布／水やりの、そのあと |
| ナイト・リレー | 空箱の着く音／数字の見える小窓／測り終えた板／空でも、一つ |

リレーの追加作業票は本編第四章の結果を明示的に確認したあとに開く。交換ブラシを納めた場合も、今回は納めないと決めた場合も対象。注文を読んだだけ、納品直後、初めて到着しただけでは開かない。他の駅の依頼は本編進行を条件にしない。

完了時に金銭・荷物・受領記録を同時保存。再送で二重払いにならない。購入品は未使用なら仕入れ先で原価返品、預かり物は依頼元へ返せる。完了後に別の星から再訪すると設備や置き場所が変わり、その後の会話と住民の雑談が出る。配送先と依頼元の変化はそれぞれの到着で反映する。猫が箱に来る、庭師が札を返すといった演出は完了条件ではない。

依頼状態は `sidequests.version=4`。以前の4件・8件・12件のセーブを順に検証して追加移行し、取引履歴・途中の会話・運送中の荷物・本編の読了記録を保持する。共通本文は `src/game/sidequests-content.js`、判定は `sidequests.js`、追加設備の描画は `src/client/sidequest-scenes.js` と各都市の既存描画に分ける。設備は保存状態、日常動作は画面の進行時計を使う。

## 音楽と環境音

音のボタンから、オリジナルBGM「窓辺のワルツ」「琥珀のホーム」「遠い日のオルゴール」を選べる。柔らかな鍵盤、電気ピアノ、オルゴールの3曲調。各16小節を音声バッファに一度描き、前の小節の残響を含んだ周期をループする。曲変更はフェードでつなぎ、背景タブでも音声の再生クロックで継続する。車窓や作業時間の一時停止とは別に、BGMの停止ボタンで操作する。
曲とBGM音量はユーザー別のD1設定に保存する。ページを開いただけでは再生しない。列車・雨の環境音と到着ベルは別の音量で調整できる。曲データは `src/client/music.js`、音の画面は `src/client/music-ui.js`。音楽ファイルの外部取得は行わない。

## 駅間時間とポモドーロ

「時間・到着ベル」で設定する。初期値は従来の周遊テンポを維持し、指定時だけ発車→到着を30秒〜24時間で設定できる。停車時間は別枠。走行時間の変更は次の発車から有効。
ポモドーロは25分作業・5分休憩・4回ごと15分の長い休憩が初期値。「この時間にやりたいこと」を任意で120文字まで記入でき、開始後は画面内と設定画面の残り時間の下に表示する。目標は設定とともにユーザー別に保存し、一時停止・休憩中も表示、タイマー終了時は隠す。起動中は車窓のタイマー直下で「タスクを追加」を開いて入力する。追加欄は初期状態で閉じ、保存できたら再び閉じる。タスク一覧は表示したまま、「完了」で一覧から削除できる。未完了タスクは各120文字・20件まで、ユーザー別D1に保存して次回へ引き継ぐ。タイマー終了では消さず、セーブ初期化では消去する。各時間は秒単位で指定可能。作業期限で次の駅への到着を保存してベルを鳴らし、休憩後に発車する。手動移動では中止し、下車・会話・保存エラーでは停止する。
別タブでも実時間で計時し、描画速度と分離。ブラウザの停止・端末スリープによる遅延時は一度だけ期限を処理し、過ぎた複数区間を追いかけない。再読込・閉じたページから自動再開しない。実行中の計時と完了回数はこのタブ内、設定は既存のユーザー別D1セーブに保持する。
到着ベルは環境音と独立した音量・オン／オフ・試聴付き。ブラウザの音声制限に従い、ユーザー操作後に音を有効化する。バックグラウンドやスリープからの復帰時は音が遅れる場合がある。

## 保存と再開

ログインした旅の正本はD1。名前・現在地・会話・金銭・荷物・取引・章・終章読了を保存する。
ゲストの記憶はページを閉じるまで。非公開サイトの入口で必要な所有者認証と、ゲーム内の保存状態は区別する。
下車中は「旅の記録」から保存して中断できる。終章はページ送りごとに保存し、再読込で同じページを開く。読了後は再ログイン時に強制再生しない。

`schemaVersion=1`、`contentVersion=finale-2026-09-07`。Phase2A〜2E・第二〜四章の保存形式を読み込み時に変換し、次の操作で確定する。
旧「エンディング」は第一章を振り返った記録として保持。途中の会話・荷物・判断をリセットしない。
署名付きバックアップは同じサイト・同じアカウントへ復元可能。古い形式も署名検証後に変換する。

「旅の記録」→「セーブデータを初期化する」で、確認画面のチェック後に自分の旅を初期化できる。名前・音・時間・表示設定を維持し、現在地を九龍、所持金を120 crに戻す。荷物、会話、手帳、本編、24件の依頼、設備の記憶は新規状態になる。初期化とチェックポイントは同じD1バッチで確定し、ユーザーID・更新番号・再送用記録を作り直さない。古いタブの上書き、初期化の再送による新しい旅の消去を防ぐ。初期化前に書き出した署名付きバックアップからの復元は可能。確認画面の表示だけでは初期化せず、保存未確認時も成功扱いにしない。

## 実装の分担

- `content/conversations.json`, `content/scenario.json`: 会話・物語の共通コンテンツ。
- `src/game`: 画面に依存しない進行判定。各章の状態と共有の金銭・ひと箱の棚を分離。
- `src/client`: 画面・Canvas描画・操作。`scripts/sync-game.mjs`が公開モジュールを同期。
- `src/server/api.js`: 本人にひもづく行動API、署名バックアップ、再送・競合検出。
- `app/api/[...path]/route.ts`: Sitesが検証した認証ユーザーIDへの接続。
- `db/schema.ts`, `drizzle/`: D1スキーマと公開時のマイグレーション。

ブラウザは「所持金を増やす」ではなく「この品を売る」を送信する。サーバーが条件・価格・結果を判定し、D1の同一バッチで記録と再送用レシートを確定する。
失敗した操作を保存済みとは表示しない。再試行は同じ操作ID。別タブの古い更新は競合として止める。

## 認証・運用

Sitesが検証して注入する `oai-authenticated-user-id` をサーバーで取得し、HMACとゲーム独自のplayer IDで対応付ける。本文・クエリで本人を切り替えない。メールや実名はDBに保存しない。
**`IDENTITY_KEY`を再生成・変更しない。** 失うと既存記録との対応とバックアップの署名検証が失われる。
既存D1の初期化・全削除はしない。スキーマ変更時は新しいマイグレーションを追加し、適用済みSQLは編集しない。
プレイヤー単位の署名バックアップは、D1全体の災害復旧の代替ではない。

公開用ビルド後に `npm run test:game`。API、SQLiteアダプター、実際の公開用WorkerをMiniflare/workerd＋D1で検証する。
終章は72通りの判断の組合せについて、文面・旧セーブ移行・途中再開・失敗時ロールバック・再送・バックアップ復元・読了後の継続を確認する。
実行結果と画面確認範囲は `docs/FINAL_RELEASE_QA.md` を参照。
